# Mimir Jev (SystemOne) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route the model `cubbit/mimir-jev` to Mimir's `/systemone` typed-judge endpoint, translating Anthropic Messages requests in and calibrated yes/no JSON out, so Claude Code can consult it like the other Mimir models.

**Architecture:** Requests for the jev model are intercepted in `ServeHTTP` (alongside the existing `count_tokens` special case) before the chat-completions translation. A new `jev.go` holds the whole leg: extract (question, state-text) from the request, POST to `/systemone`, translate the answer into one Anthropic Messages reply (JSON or synthesized SSE). No new config; the model name rides the existing `cubbit/` prefix.

**Tech Stack:** Go standard library only.

**Spec:** `docs/superpowers/specs/2026-11-17-mimir-jev-design.md`

## Global Constraints

- Go standard library only — no new dependencies (`go.mod` untouched).
- Metadata-only log: never prompt text, the question, the state text, or credentials.
- No new CLI flags, environment variables, or config struct fields; the model name is hardcoded like the effort-map defaults.
- One attempt per request: a failed SystemOne call becomes a sanitized Anthropic error; the router never retries. The handler (the new jev branch) classifies errors; no retry logic anywhere below it.
- SystemOne call timeout: 30 seconds.
- `verify` command when one is named: `go test ./...` and `go vet ./...` must both pass.

## Review Focus

Inputs the spec covers only in passing; each is pinned to its owning task's tests:

1. **A fresh-subagent request: one user message, nothing else.** Expect: judged as a claim on its own — state.text = the question text, never an empty state, never a 500 from the upstream. (Task 1 test)
2. **Last user message with no text (images or tool_use only).** Expect: local 400, nothing sent upstream. (Task 1 test)
3. **`stream: true` request (Claude Code's default).** Expect: a strictly valid Anthropic event sequence carrying the JSON as one text block. (Task 2 test, and through the gateway in Task 3)
4. **Gateway in `anthropic` mode receiving a jev request.** Expect: a clear 400 naming the limitation, not a forwarded request to `/anthropic`. (Task 3 test)
5. **SystemOne returns 500, or a 200 with a body missing `answers.q`.** Expect: translated, sanitized error (never raw internal details as a bare 502 with leaks); log line records the status. (Task 2+3 tests)
6. **Prompt text never reaches the log.** (Task 3 test, `secretText` pattern like `TestGatewayOpenAIStream`)

- [ ] **Step 3: Implement `toSystemOne` and `jevModel` in `jev.go`**

Parse the same request shape `toChatCompletions` does (a local struct with `Messages []json.RawMessage` and `System json.RawMessage` is enough — the fold machinery is not needed and must not be applied). The last message whose `roleOf(...)` is `"user"` is the question turn; its text blocks (via `blocksOfContent` + `toolResultText` for `tool_result` — though a question turn is normally text-only) joined by `"\n\n"`. ```go

`pYes=0.5` → `verdict == "yes"` (spec: yes when `p_yes >= 0.5`).

```go

```
`stream=true`: run the bytes through `checkAnthStream(t, out)` — it must pass the strict parser with exactly one `text` block; the accumulated `blocks[0]["text"]` parses as the same JSON object as the non-stream case; `res.stopReason == "end_turn"`; usage zeros.

Run: `go test -run 'TestParseSystemOne|TestJevReply' ./...`
Expected: FAIL — functions undefined.

- [ ] **Step 3: Implement `parseSystemOne` and `jevReply` in `jev.go`**

`parseSystemOne`: decode into a struct mirroring the wire answer (`answers.q.probabilities.{yes,no}` and `.confidence`, both float64; `noul` ignored), validate all three are in `[0,1]`.

`jevReply`: `"yes"` iff `pYes >= 0.5`. The reply text is one JSON object:
`{"verdict": "yes"|"no", "probabilities": {"yes": pYes, "no": pNo}, "confidence": confidence}` — byte-compatible with the `jev --json` shape the skills print (spec requirement; no extra fields).

- Non-stream: build the same map `fromChatCompletion` builds for a text-only reply (`id` `"msg_jev"`, `stop_reason "end_turn"`, `usage` `{"input_tokens":0,"output_tokens":0}`), `content` one `{"type":"text","text":<json line>}`, and `marshal` it.
- Stream: an in-memory `bytes.Buffer` emitting exactly the house event shapes (copy field-for-field from `chatStream.start` / `openBlock` / `end` in `openai.go`): `message_start` (message id `"msg_jev"`, model, usage zeros) → `content_block_start` index 0 with `{"type":"text","text":""}` → `content_block_delta` index 0 with `{"type":"text_delta","text":<json line>}` → `content_block_stop` index 0 → `message_delta` with `{"stop_reason":"end_turn","stop_sequence":nil}` and usage zeros → `message_stop`. Same `"event: <name>\ndata: <json>\n\n"` framing, `marshal`-encoded, no HTML escaping.

- [ ] **Step 3: Implement the branch**

In `proxy.go` `ServeHTTP`, inside `if shape != nil && mimir`, immediately after the `count_tokens` block (which stays first, so `count_tokens` keeps working for the jev model):

```go
if model == jevModel {
    g.serveJev(w, r, ri, src)
    return
}
```

(`src` is the decoded body the surrounding block already computed for mimir-routed requests.)

In `jev.go`, `func (g *gateway) serveJev(w http.ResponseWriter, r *http.Request, ri *reqInfo, src []byte)`:

1. `g.cfg.mimirAPI != "openai"` → `writeError(w, 400, "router: cubbit/mimir-jev needs the openai Mimir API (MIMIR_API=openai)")`, set `ri.status`, `ri.errMsg`, `ri.finish()`, return.
2. `toSystemOne(src)` error → 400 through `writeError`, log likewise.
3. Build the POST body per the spec wire format: `{"state":{"text":state},"questions":{"q":{"type":"noul","criteria":{"true":{"text":question},"false":null}}}}` (marshal with the house `marshal`).
4. Request to `g.mimirU` with `/systemone` appended (the config URL already ends in `/v1`), `Authorization: Bearer <g.mimirKey>`, our `g.transport` in an `http.Client{Timeout: 30s}`. One attempt, no retry (Global Constraints).
5. Read the response (limited, `io.LimitReader` like `modifyResponse` does).
   - non-2xx → `st, eb := translateOpenAIError(resp.StatusCode, payload)`; `w.Header Content-Type application/json`, `WriteHeader(st)`, write `eb`; set `ri.status`, `ri.errMsg = errorMessage(payload, resp.Header.Get("Content-Encoding"))`... — no: reuse the plain `string(payload)`-derived message the error body carries via `errorText(payload)`; log it. Keep the log message the translated one, matching `TestGatewayJevUpstreamErrorIsTranslated`.
   - `parseSystemOne` error → same path with `translateOpenAIError(502, ...)`. Never echo the raw upstream body to the client.
6. Success: `nb := jevReply(jevModel, pYes, pNo, conf, stream)` where `stream` comes from the request's `"stream"` field (parse next to `toSystemOne` or read it in `serveJev` — one place, test-covered). Set content type by mode; write via `countingBody{rc: io.NopCloser(bytes.NewReader(nb)), ri: ri}` + `io.Copy` + Close (so `resp_bytes` and the finish semantics match the other legs). Before writing: `ri.status = 200`; `ri.rec["jev_verdict"], ri.rec["jev_p_yes"], ri.rec["jev_confidence"] = verdict, pYes, conf`.
7. `r.Context()` cancellation mid-call → return without writing; `ri.errMsg = "client went away"` if `ri.ctx.Err() != nil`, else transport error; still `translateOpenAIError(502, ...)` to the client when the request is still alive. Keep it simple: mirror `errorHandler`'s classification with `errors.Is(err, context.Canceled)`.

   Both `translateOpenAIError` paths and the 502 path set `ri.finish()` exactly once (ideally once, at the end of the function).
